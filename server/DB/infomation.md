# 数据库

## DDL、DML、DQL、DCL

| 标识    | 全称                             | 说明                                                                    | 用途 |
|-------|--------------------------------|-----------------------------------------------------------------------|----|
| `DDL` | （Data `Definition` Language）   | 数据`定义`语言，主要是进行定义/改变表的结构、数据类型、表之间的链接等操作。常用的语句关键字有 CREATE、DROP、ALTER 等。 |
| `DML` | （Data `Manipulation` Language） | 数据`操纵`语言，主要是对数据进行增加、删除、修改操作。常用的语句关键字有 INSERT、UPDATE、DELETE 等。         |
| `DQL` | （Data `Query` Language）        | 数据`查询`语言，主要是对数据进行查询操作。常用关键字有 SELECT、FROM、WHERE 等。                     |
| `DCL` | （Data `Control` Language）      | 数据`控制`语言，主要是用来设置/更改数据库用户权限。常用关键字有 GRANT、REVOKE 等。                     |



## 事务隔离级别



`数据库事务隔离级别`是数据库系统为了保证事务的并发执行时数据的一致性和完整性而设置的一种机制。



不同的隔离级别可以解决不同的并发问题，如脏读、不可重复读和幻读。

### SQL标准定义的四种事务隔离级别：

#### `读未提交`（Read Uncommitted）



**特点**：最低的隔离级别，允许脏读、不可重复读和幻读。



**说明**：事务可以看到其他事务未提交的修改。



#### `读已提交`（Read Committed）



**特点**：防止脏读，但允许不可重复读和幻读。



**说明**：事务只能看到其他事务已经提交的修改。



#### `可重复读`（Repeatable Read）



**特点**：防止脏读和不可重复读，但允许幻读。



**说明**：在一个事务内，多次读取同一数据会返回相同的结果，即使其他事务在此期间修改了数据。



#### `串行化`（Serializable）



**特点**：最高的隔离级别，防止脏读、不可重复读和幻读。



**说明**：事务串行执行，即在同一时间只允许一个事务运行，从而避免了所有并发问题。



### 选择合适的隔离级别



选择合适的隔离级别需要权衡数据一致性和系统性能。一般来说：



`读未提交`：性能最好，但数据一致性最差，通常不建议使用。



`读已提交`：大多数数据库系统的默认隔离级别，适用于大多数场景。



`可重复读`：适用于需要保证事务内数据一致性的场景，如财务系统。



`串行化`：性能最差，但数据一致性最好，适用于对数据一致性要求极高的场景。



### 数据库默认隔离级别

不同的数据库系统可能有不同的默认隔离级别：

`MySQL`：默认隔离级别为可重复读（Repeatable Read）。

`PostgreSQL`：默认隔离级别为读已提交（Read Committed）。

`Oracle`：默认隔离级别为读已提交（Read Committed）。

`SQL Server`：默认隔离级别为读已提交（Read Committed）。

### 设置事务隔离级别

在SQL中，可以使用以下语句设置事务隔离级别：

```sql
SET TRANSACTION ISOLATION LEVEL [隔离级别];
# 例如，设置为读已提交
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
```
